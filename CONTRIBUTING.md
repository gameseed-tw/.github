# Contributing to GameSeed 🌱

**Growing Game Creators Everywhere.**

[English](CONTRIBUTING.md) · [繁體中文](CONTRIBUTING.zh-TW.md)

Thank you for helping GameSeed grow! GameSeed is an emerging, Taiwan-initiated network for game-development education, creative experimentation, and talent incubation. We welcome contributions from students, educators, independent game developers, mentors, and communities worldwide.

> **Current status:** GameSeed is in early planning and development. Not every project or proposed collaboration is open for contributions yet. Follow the instructions in the specific repository and check with its maintainers before starting substantial work.

## 1. Ways to contribute

You can help by:

- **Learning resources:** tutorials, teaching slides, exercises, examples, and translations.
- **Game development:** playable prototypes, reusable Unity or other engine templates, tooling, and documentation.
- **Quality and accessibility:** testing, reproducible bug reports, accessibility feedback, and usability improvements.
- **Community knowledge:** game-jam materials, workshop ideas, mentoring resources, and lessons learned.
- **Collaboration:** proposals for educational partnerships, cross-campus projects, and responsible open-source initiatives.

Contributions need not be code.

## 2. Before you start

1. Read the specific repository's `README.md`, license, and any local contribution or development instructions.
2. Check its Issues or Discussions **if enabled** to see whether the topic is already being handled.
3. For a significant change, propose the scope in an Issue or contact the repository's maintainers using its published channels **before** doing extensive work.
4. Choose a manageable task. New contributors are welcome to start with documentation, examples, or small fixes.
5. Do not assume that joining a GitHub repository makes someone a formal GameSeed member, representative, mentor, or partner.

**Repository-specific rules take precedence** over these shared guidelines.

## 3. Submitting changes

For a repository that accepts pull requests:

1. Fork the repository or create a working branch if you have permission.
2. Make focused changes and keep related documentation up to date.
3. Run the tests, build, formatting, or manual checks described in that repository. If you cannot run them, say so.
4. Open a Pull Request explaining **what changed**, **why it matters**, **how it was checked**, and any remaining limitations.
5. Respond constructively to feedback. Maintainers decide when changes are ready to merge.

Suggested PR checklist:

- [ ] I followed the repository's contribution and license requirements.
- [ ] My change is clearly described and limited in scope.
- [ ] Relevant documentation and language versions were updated.
- [ ] Applicable tests or manual checks were run, or limitations were disclosed.
- [ ] I have the rights and permission to contribute all included materials.
- [ ] No personal data, credentials, or non-public institutional materials were included.

## 4. Content, attribution, and responsible use

- **Copyright and licenses:** Contribute original work or materials you have permission to share. Clearly identify third-party assets, citations, authors, and relevant license terms. Each project has its **own license**; this organization-wide file does not grant a universal license.
- **Academic and educational materials:** Respect institutional policies, student consent, research ethics, and unpublished work. Never upload student records, assessment data, private participant data, internal proposals, or confidential materials without explicit authorization.
- **Security:** Never commit passwords, API keys, tokens, secrets, or private connection settings. Follow repository-specific security-reporting instructions; do not publicly disclose exploitable vulnerabilities before maintainers can address them.
- **AI-assisted contributions:** AI tools may support drafting, coding, translation, and review, but a human contributor must verify accuracy, licenses, safety, and functionality. Disclose meaningful AI assistance in the PR when it affects provenance, evaluation, or reproducibility.
- **Media and large files:** Use formats and file-storage practices defined by each project. Seek maintainer approval before adding large game assets or binary files.
- **Accessibility and localization:** Prefer clear instructions, readable layouts, and inclusive language. Use English for shared international documentation when practical; Traditional Chinese translations are welcome.

## 5. Collaboration and governance

We value respectful discussion, constructive reviews, educational openness, and credit for contributors.

Being a contributor is **not equivalent** to being a founding member, staff member, organization owner, or official partner. Membership, repository permissions, mentor appointments, and institutional partnerships are handled separately by authorized organizers.

GameSeed's formal governance, participating faculty, and partner roster are still being developed. We will publish confirmed roles and collaboration mechanisms when agreed upon.

## 6. Language and contact

- **Primary shared documentation:** English.
- **Traditional Chinese guide:** [CONTRIBUTING.zh-TW.md](CONTRIBUTING.zh-TW.md).
- **Questions:** Use the relevant repository's Issues or Discussions when available. For private or institutional matters, contact the maintainers using the channel explicitly published by that repository; please do not post sensitive information publicly.
